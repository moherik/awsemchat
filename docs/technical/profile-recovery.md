# Authoritative Circle profile cancellation

Local migration11 introduces `profile_operation_cancellations`, scoped to the authenticated account, active generation and operation ID. It stores only the SHA256 digest of the exact opaque envelope and creation time. Keys, profile names/descriptions/avatar descriptors and plaintext are not added to this table.

`POST /v1/messages/profiles/cancel` accepts `{envelope:string}` with the same bounded strict envelope/body parsing as sending. Only Circle-profile envelopes are accepted; ordinary/private message cancellation is unavailable. The principal comes from the current session, never the request body. A former member/admin may reconcile their own original profile operation after leaving/closure, provided their account session/generation remains valid.

Send and cancellation share the existing per-account/generation/operation transaction lock. Cancellation checks exact committed bytes before any fence. An existing matching event returns `{state:"committed",operation,event:{id,operation,status:"sent"}}`, without retracting or changing it. Otherwise cancellation persists a fence and returns `{state:"cancelled",operation}`. Exact retries return the same outcome. A later matching send fails with409 `OPERATION_CANCELLED`; changed bytes under the same operation conflict with409 `OPERATION_CONFLICT`. A cancellation winner does not increment the Circle revision or create delivery rows. A competing successful send winner remains committed. Existing delivery state stays monotonic when its sender later reconciles the committed event.

The typed mobile client validates the operation/outcome/committed event and inherits the existing session-transition guard, redirect restriction and request timeout. It sends only the original envelope and rejects malformed or mismatched responses. This endpoint is reconciliation authority; it does not itself delete a phone's native outbox or grant permission to rewrite an uncertain queued update.

## Native recovery implementation

The native engine now exposes an exact read-only saved-profile recovery operation and exact queued-profile retirement. Recovery reads the original ciphertext even when current peer identity checks prevent sending; it does not bypass those checks for ordinary retries. Retirement removes only the matching uncommitted Circle-profile outbox entry and records an operation/digest tombstone. Confirmed profiles and ordinary messages cannot be retired. Reopened state rejects operation reuse while preserving unrelated history, receipts and peer ratchets. The tombstone ledger is bounded at1024 entries and fails closed when full; retention remains a separate obligation.

The account-bound coordinator serializes recovery with sending and reconciliation. It submits the original envelope to the authoritative cancellation endpoint before changing native state. A committed outcome confirms the original event; a cancellation outcome first completes exact avatar-intent cleanup, then retires the original pending operation. Lost replies preserve the pending update, and account changes or mismatched responses prevent subsequent writes. Circle details provides an explicit cancellation confirmation, including when membership/context loading is unavailable. Editing stays disabled until refresh after recovery.

Verification: five coordinator cases, sender queue ordering and Circle details recovery were written failing-first. Native failing-first cases cover exact retirement, reopening, operation reuse, preserved peer decryption and recovery following a peer identity change; supplementary cases cover capacity release and malformed tombstones. All333 mobile tests and48 Rust tests pass. The Android debug build succeeds with the new native commands. This is host/controller/build evidence, not an emulator interaction or a live native-to-HTTP recovery walkthrough.

## Remaining work

- Cancellation cleanup ordering is now restart-safe for new recoveries: the authoritative server fence precedes matching local avatar-intent release; native profile retirement happens last. Until cleanup succeeds, the existing protected native outbox retains the recovery draft. Lost cleanup replies or storage errors therefore allow repeating the exact server outcome and local release after reopening. Committed outcomes never release uploads. Account changes during cleanup prevent native retirement. This replaces the earlier post-retirement details callback; its ordering test was replaced by coordinator failure/restart tests. All340 mobile tests, TypeScript, lint and whitespace checks pass. The recreated-coordinator probe uses persistent in-memory storage fixtures; actual Android process-kill acceptance remains skipped.
- Release compares the complete saved intent under the vault queue; epoch, descriptor and original base revision must match. It clears only local protected metadata/ciphertext, not remote storage. A cleanup interrupted under the older ordering can still leave an orphan intent without a native draft; missing outbox state alone is not authorization to discard it. Stale uploads without a cancelled profile, filesystem orphan removal and remote orphan retention remain open.
- Saved-profile discovery is implemented in a native Saved Circle updates page, reachable from settings and Your Circles. It reads queued native profiles independently of remote membership and opens existing Circle details recovery. Reads validate unique operations/Circles, exact routing, revisions and private profile payloads; malformed or competing records fail closed. Account/reset transitions invalidate in-flight reads and hide names. Four failing-first controller cases and a supplementary discovery-to-closed-Circle recovery integration case pass; all345 mobile tests pass, with TypeScript/lint/whitespace checks. This is controller/static evidence; actual native navigation and screen acceptance remain skipped.
