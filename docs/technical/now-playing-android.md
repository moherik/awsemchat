# Android Now Playing feasibility

AwsemChat can discover playback from other Android apps through `MediaSessionManager.getActiveSessions`. Android allows this when the caller holds the privileged `MEDIA_CONTENT_CONTROL` permission or is an enabled `NotificationListenerService`. Android marks `MEDIA_CONTENT_CONTROL` as unavailable to third-party apps because of the privacy of media consumption, so the public route requires the user to grant notification access in Android Settings. See the [MediaSessionManager API](https://developer.android.com/reference/android/media/session/MediaSessionManager#getActiveSessions(android.content.ComponentName)), [MEDIA_CONTENT_CONTROL permission](https://developer.android.com/reference/android/Manifest.permission#MEDIA_CONTENT_CONTROL), and [NotificationListenerService API](https://developer.android.com/reference/android/service/notification/NotificationListenerService).

This access is broader than the feature needs. AwsemChat queries active media sessions and reads only session metadata (track title and artist). It does not parse notification text or forward notification content. The service permission and consent to share Now Playing with friends are separate controls: granting access alone does not share a track.

The product contract limits sharing to accepted private friends and excludes Circle messages. Updates are end-to-end encrypted per friend and clear when sharing is disabled or playback stops. The current implementation uses a 15-minute expiry if the sender cannot publish a stop update; the owner has not confirmed this expiry policy yet, so it remains a release decision. Missing track or artist metadata is not filled with guessed values. The Android settings screen explains the broad system permission and provides a direct settings action.

**Current state:** Native service registration, OS settings flow, warning and separate sharing control, strict metadata validation, encrypted friend fanout, clear/expiry behavior, and foreground-only refresh are implemented. Android Gradle build and controller/fanout tests pass. Real-device permission, playback, stop, Doze, and multi-account acceptance remain open. The web preview stays demo-backed.
