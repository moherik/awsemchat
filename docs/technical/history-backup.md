# Production history backup integration

Status: foundation implemented on2026-10-12; Task6 remains incomplete.

`apps/mobile/src/features/backup/history-backup.ts` connects the native durable history snapshot to the Android authenticated archive codec. `archive-codec.ts` adapts its existing executeArchive bridge and sanitizes failures. The destination receives encrypted base64 archive bytes only. A generated recovery key is returned separately for recovery UX; this service neither logs nor persists it alongside the file.

Each archive record is a self-account-scoped history container: conversationId `awsemchat.history-backup.v1`, membershipInterval `history-only`, originalAudience containing the backup owner's account ID, and a numbered entry ID. These fields describe the backup container, not the enclosed message's recipients or membership. Its encrypted payload retains the original message operation, conversation, audience, public sender keys, plaintext, direction and known creation time. Live receipt proofs, local sequence numbers, send receipts, private identity keys, ratchets and session credentials are excluded.

Restore authenticates the complete archive in native code, validates every container and parses every payload before one transactional native import. The native importer validates message fields and preserves its existing state on failure. All restored records become archival. Repeated identical imports are deduplicated. A current account/device/session binding is checked after asynchronous export/encode/decode and before storage/import; the eventual production history adapter must also retain its native account-operation guards. File storage adapters must persist encrypted bytes only.

The archive bridge now accepts all768 records supported by the current durable store. The existing format already authenticates each record frame, its position and a complete manifest/end digest under one recovery key. Bounds are256KiB payload per frame,260KiB frame,16MiB aggregate plaintext,17MiB encrypted archive and32MiB bridge JSON input. Native history import alone may use an8MiB request; live messaging retains128KiB request limits. Sealed state remains8MiB. These bounded foundations still need scalable storage and streaming before general backup completeness can be claimed. Local Android file export/import and the account-bound recovery screen are now connected. Drive OAuth/upload, scheduling, persistent last-success metadata, media backup and replacement-phone acceptance remain unfinished.

## Message deletion reconciliation (2026-10-15)

Both local and Drive restore read every page of the signed-in account's server redaction ledger before importing archive contents. Modern history matches by immutable server event ID; older records match by the full conversation, original audience, operation and both sender public keys. Invalid responses, ambiguous legacy matches, network failure and account replacement abort before message or sticker import. This prevents an old archive from restoring a message already deleted for everyone. New archive creation also reads native pending deletions and omits matching messages until the server confirms deletion, using exact event IDs or the same legacy descriptor. This protects a newly made backup during an offline retry window.
