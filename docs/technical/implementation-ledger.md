## Backend stack decisions — 2026-10-16

Spec review found the technology table stale against later decisions and three open decisions missing from its section 16 list; findings were reported to the user and resolved by direct decisions rather than a spec rewrite. Backend: Elixir/Phoenix single service replaces the spec's Go service (user decision after trade-off discussion). ejabberd as a separate chat server was considered and dropped: React Native XMPP client reliability was the dominant risk and Phoenix Channels covers offline queue, receipts, and fan-out directly. E2E protocol: vodozemac (Olm/Megolm) selected over libsignal (AGPL, unsupported outside Signal, no Hermes binding), MLS/OpenMLS (young mobile bindings, parked), and cryptobox/libsession. Rationale: MPL-2.0, the existing passing host probe, Megolm rotation matching Circle membership epochs, and built-in key export/import serving backup key material. Server remains a relay: no content keys. Implementation sequencing recorded in the [Phoenix chat backend plan](../superpowers/plans/2026-10-16-phoenix-chat-backend.md); validation-first ordering preserved (vodozemac Android device spike gates all backend feature tasks). The spec's Go references and its section 13 table await a dated amendment; no code written under this decision yet.
