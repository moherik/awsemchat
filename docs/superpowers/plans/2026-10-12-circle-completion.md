# Circle completion implementation plan

Execution: inline TDD in the original checkout; no subagents. Preserve existing work. The owner requested complete Circle functionality, testing, and current project status after each finished task. Emulator interaction testing was previously skipped; automated host/native/backend tests remain required.

Accepted contracts: `docs/technical/social-service.md`, `circle-creation.md`, `circle-profiles.md`, `ui-backend-handoff.md` and the approved MVP plan. Circles are private, consent-based, and limited to20 members. A last admin chooses a successor before leaving unless alone, when leaving closes the Circle. New members cannot read earlier messages or Moments. Profile/media plaintext stays client-owned and encrypted.

MVP scope update (2026-10-15): custom Circle emoji are deferred. This Circle implementation covers shared stickers and standard emoji reactions only; the reserved protocol kind does not imply an Android creation, picker, or message flow.

## Sequence and owners

Membership state belongs in `apps/mobile/src/features/social/circle-membership.ts`, its screen/selector beside the existing details screen, and runtime controller caching in authentication runtime. HTTP DTO validation belongs in social API. Mutation idempotency belongs in the Go Circle service and migration ledger rather than a UI guess. Profile audience/revision work uses the existing encrypted sender, native durable outbox and Circle relay authorization. Media/collections require their actual storage and encryption owners; demo stores are not production substitutes.

Each behavior starts with a failing test. Run the complete mobile suite with localhost fixture permissions, TypeScript, uncached lint and whitespace checks per completed client task. Backend changes require uncached real-PostgreSQL race tests and vet; native changes require Rust tests and host/native archive checks. Record performed checks separately from skipped emulator/provider walkthroughs.
